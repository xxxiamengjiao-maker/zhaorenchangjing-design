🎯 核心原则

1所有「找人」场景统一收归到找人意图，从乐享知识库中完全剥离，解决时效性差、答案不准的问题
2能调实时 API 的场景 → 优先走接口；暂无 API 的场景 → 走行家助手后台线下表维护（业务侧自行录入）
3后续方向：产线 / SKU 模糊匹配能力持续完善，逐步替换线下表

子意图一：找产线 AI行家助手-找产线 Type 1
场景 1a 按 SKU编码 / 物料名称 找产线同事 🟢 实时接口 · 商品中心
触发示例 「AA0061的产线是谁」「口罩的产线经理是谁」「断路器找谁对接」
数据来源 商品中心 · 商品列表接口@吴雪娟
入参 skuNo（SKU编码）或 物料描述（模糊匹配）
交互流程
① 用户输入关键词搜索
按 SKU编码 → 精确匹配，直接返回结果
按 物料名称 → 模糊匹配，可能命中多条 → 先返回商品列表供用户选择
② 用户选中商品后
返回该商品对应的 商品经理（= 产线负责人）信息
MVP出参 ✅ 商品经理姓名（= 产线负责人）
接口需求 需要一个「按 SKU编码或物料名称查负责人」的接口，请确认是否有现成接口，并提供出入参文档 @吴雪娟
Gap说明 ⚠️ BD、Sourcing、技术支持等角色此接口暂无，见场景1b
场景 1b 按 产线名称（物料组 or SKU） 找产线同事 🔀 多来源
触发示例 「MRO润滑的产线负责人是谁」「FA产线的技术支持找谁」「MRO产线的采购是谁」
逻辑说明 产线名称 = 物料组；先按物料组查到一个 SKU，取第一个 SKU 对应的商品经理 / 采购
可查角色
a. 产线负责人（商品经理）
同场景1a，走商品中心接口@吴雪娟
b. 采购
产线（物料组）→ 对应多个SKU → 取第一个SKU找采购，走商品中心接口@吴雪娟
c. 技术支持、Sourcing
走 QTS 接口@李金朋
d. 数据
找张喻要线下表，录入行家助手后台@张喻（一件件来）
