🔍 找人场景方案设计

AI行家助手 · 找人意图重构方案 · MVP版本

API优先 知识库兜底 统一意图入口 Type 1 / 2 / 33 / 34 / 35

🎯 核心原则

1所有「找人」场景统一收归到找人意图，从乐享知识库中完全剥离，解决知识库时效性差、答案不准的问题
2能调实时 API 的场景 → 优先走接口，保证准确性和时效性
3暂无 API 的场景 → 走乐享知识库兜底，意图已独立，后续可随时替换为接口

❓ 待确认问题（需找对应开发 / 业务方确认）

1 【找产线 场景1b】商品中心是否支持按产线名称检索？
当前商品中心接口入参为 skuNo 和 物料描述，未见产线名称字段。需确认：是否存在以产线名称为入参的查询能力？若支持，场景1b可切换为实时接口；若不支持，继续走后台线下表维护查找。
👉 找商品中心对应开发确认
2 【坤合仓库 场景5a】找的是「负责人」还是「值班人」？
当前写的是「坤合仓库负责人」，但原始标注为「找值班 - 仓库」，两者含义不同，需明确后更新触发示例与知识库内容。
👉 找业务方确认

子意图一：找产线 AI行家助手-找产线 Type 1
场景 1a 按 SKU编码 / 物料名称 找产线同事 🟢 实时接口
触发示例「AA0061的产线是谁」「口罩的产线经理是谁」「断路器找谁对接」
数据来源商品中心 · 商品列表接口
入参skuNo（SKU编码）或 物料描述（模糊匹配）
MVP出参✅ 商品经理姓名（= 产线负责人）
Gap说明 ⚠️ BD、Sourcing、技术支持等角色接口暂无
二期：去后台线下表中维护查找
多结果处理物料名称模糊搜索可能返回多条 → 展示列表让用户选择具体商品后再返回负责人
场景 1b 按 产线名称 找产线同事 🟡 待确认 → 实时接口 / 线下表
触发示例「MRO润滑的产线负责人是谁」「FA产线找谁」
优先策略
① 优先：商品中心实时接口
❓ 待确认：商品中心是否支持按产线名称检索
若支持 → 走实时接口，入参为产线名称
OR
② 兜底：后台线下表维护查找
若商品中心不支持 → 走后台线下表（人工维护）
可查角色产线负责人、技术支持、数据、Sourcing、采购、招商经理等（按后台维护内容为准）

子意图三：查值班 AI行家助手-查值班 Type 33
